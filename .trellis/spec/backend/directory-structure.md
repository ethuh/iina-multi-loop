# Core App Directory Structure

This repository is an IINA macOS app, not a backend service. Treat this spec area as the "core app / playback / tooling / data boundary" layer.

## Top-level layout

- `iina/` contains the main AppKit application, playback orchestration, mpv integration, plugin runtime, preferences, localization, assets, and XIBs.
- `deps/` contains vendored headers and downloaded runtime dependencies. `deps/include/` is checked in; `deps/lib/` and `deps/executable/` are populated by scripts such as `other/download_libs.sh`.
- `Configs/` contains Xcode `.xcconfig` files. `Configs/Shared.xcconfig` sets shared warnings and `SWIFT_VERSION = 5.0`; `Configs/Deployment.xcconfig` sets deployment targets.
- `other/` contains maintenance and build scripts, including dependency download and generated mpv binding scripts.
- `iina-cli/` contains the Swift CLI launcher wrapper for `IINA.app`.
- `iina-plugin/` contains the Swift CLI for creating, packing, linking, and unlinking JavaScript plugins.
- `browser/` contains Chrome/Firefox "Open in IINA" extension files.
- `OpenInIINA/` contains the Safari extension.

## Core app boundaries

- App startup and URL scheme handling live in `iina/AppDelegate.swift`. It registers the `kAEGetURL` Apple Event handler and routes `iina://open` and `iina://weblink` actions.
- Playback orchestration belongs in `iina/PlayerCore.swift`. This class owns player instances, playlists, `PlaybackInfo`, plugin instances, `FFmpegController`, and the `MPVController` instance.
- Direct mpv API calls are limited by `CONTRIBUTING.md`: only `iina/MPVController.swift` and `iina/VideoView.swift` may call mpv APIs directly. Other code should route playback operations through `PlayerCore` methods or existing controller APIs.
- Window-level behavior belongs in `iina/MainWindowController.swift` or `iina/PlayerWindowController.swift`. Examples: sidebars, OSC, fullscreen/PiP behavior, scroll/mouse handling, and UI synchronization.
- Preferences are centralized in `iina/Preference.swift`. New persistent preference keys should be added to `Preference.Key`, with defaults and typed accessors following nearby existing patterns.
- Plugin runtime code is in `iina/JavascriptPlugin.swift`, `iina/JavascriptPluginInstance.swift`, `iina/JavascriptMessageHub.swift`, and `iina/Plugin*View*.swift`. Do not confuse these with the separate `iina-plugin/main.swift` development CLI.
- URL-opening integrations outside the main app are thin adapters: `browser/Chrome_Open_In_IINA/common.js` builds `iina://open?...`; `OpenInIINA/SafariExtensionHandler.swift` builds `iina://weblink?url=...`.

## Generated and vendored files

- Do not edit `iina/MPVCommand.swift`, `iina/MPVOption.swift`, or `iina/MPVProperty.swift` directly. They are generated by `other/parse_doc.rb` from mpv documentation.
- Do not hand-edit generated document iconsets under `iina/Assets.xcassets/DocIcons/` when using `other/integrate_doc_types.rb`.
- Treat headers under `deps/include/` as vendored inputs that must match the dylibs in `deps/lib/`.

## Real examples

- Multi-segment loop core state and persistence are in `iina/MultiLoop.swift`, while the sidebar management UI is separate in `iina/MultiLoopViewController.swift`.
- `iina/PlayerCore.swift` exposes high-level playback state such as `abLoopA`, `abLoopB`, `multiLoop`, `openURLs`, and player-instance selection.
- `iina/MPVController.swift` owns mpv event observation and has the dedicated event queue `com.colliderli.iina.controller`; comments there explicitly warn not to process slow work on that queue.
